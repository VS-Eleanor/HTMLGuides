Password Expiration Troubleshooting Guide

flexHR ESS/HRSS - For Helpdesk & Support Staff

Before you start: You will need access to SQL Server Management Studio (SSMS) connected to the flexHR database. All queries below can be copied with the "Copy" button and pasted directly into SSMS.
Error CodeError MessageWhat Happened
GEN99002 You have exceeded the number of password attempts. User tried logging in too many times with wrong password. Account is locked.
GEN99120 Your new password has expired. Please reset your password and retry as soon as possible. User was given a reset password but took too long to change it.
GEN99121 Your password has expired. Please reset your password. User's regular password has expired because they haven't changed it in a long time.
GEN99122 Your new password has expired. Please contact the helpdesk to reset your password. A new user was given an initial password but didn't log in and change it in time. Admin must reset.
GEN99123 The login id does not exist. Username not found in the system. Check spelling.
GEN99126 Your old password is invalid. User entered wrong current password when trying to change it.
GEN99127 Invalid user/tenant info. User account or tenant configuration issue. Escalate if persists.
GEN99128 User password information is not found. Password record is missing from database. Escalate to developer.

Run this query in SSMS. Replace username_here with the affected user's login ID.

SELECT
    u.UserName        AS [Login ID],
    u.UserFullName    AS [Full Name],
    u.Email           AS [Email],
    u.EmployeeNo      AS [Employee No],
    u.TenantId        AS [Tenant ID],
    up.PwdState       AS [Password State],
    CASE up.PwdState
        WHEN 0 THEN 'None'
        WHEN 1 THEN 'OK (Active)'
        WHEN 2 THEN 'LOCKED (Too many failed attempts)'
        WHEN 3 THEN 'Reset by Admin (Pending change)'
        WHEN 4 THEN 'Expired (Must change)'
        WHEN 5 THEN 'New User (Must change initial password)'
        WHEN 6 THEN 'Reset Invalid Count'
        WHEN 7 THEN 'New User Reset Invalid Count'
        WHEN 8 THEN 'SAML Login'
    END               AS [Password State Description],
    up.PwdNvrExpired  AS [Never Expires? (1=Yes, 0=No)],
    up.EntryDate      AS [Password Created On],
    up.ModifyDate     AS [Password Last Changed On],
    up.NoofInvalidAttempts AS [Failed Login Attempts],
    up.IsActive       AS [Account Active? (1=Yes, 0=No)]
FROM [User] u WITH(NOLOCK)
INNER JOIN UserPassword up WITH(NOLOCK) ON u.UID = up.UID
WHERE u.UserName = 'username_here'

Understanding the Results

Password StateWhat It MeansRelated Error
1 - OKPassword is active and workingNo error expected
2 - LOCKEDToo many failed login attemptsGEN99002
3 - Reset by AdminAdmin reset the password, user hasn't changed it yetGEN99120 if expired
4 - ExpiredRegular password expired (too many days since last change)GEN99121
5 - New UserNew user hasn't changed their initial passwordGEN99122 if expired
8 - SAMLUser logs in via SSO (SAML), no password neededN/A
Key columns to note:
• Tenant ID - You'll need this for Step 2.
• Password Last Changed On - This is compared against the expiry settings to determine if the password has expired.
• Never Expires? - If this is 1, the password should never expire. If the user still gets an error, escalate to a developer.

Run this query to see the password policy settings. Replace TENANT_ID_HERE with the Tenant ID from Step 1.

SELECT
    Name AS [Setting Name],
    Value AS [Current Value],
    [Desc] AS [Description],
    CASE
        WHEN Name LIKE '%NewUserDuration%'
            THEN CONCAT(Value, ' minutes = ', CAST(CAST(Value AS INT) / 1440.0 AS DECIMAL(10,1)), ' days')
        WHEN Name LIKE '%ChangePasswordDuration%'
            THEN CONCAT(Value, ' days')
        WHEN Name LIKE '%ValidAttemptCount%'
            THEN CONCAT(Value, ' attempts')
    END AS [Explained]
FROM SysParam WITH(NOLOCK)
WHERE Name IN (
    'Password.ChangePasswordDuration',
    'Password.NewUserDuration',
    'Password2.ChangePasswordDuration',
    'Password2.NewUserDuration',
    'Login.ValidAttemptCount'
)
AND TenantId = 'TENANT_ID_HERE'
ORDER BY Name

What Each Setting Controls

SettingUnitDefaultWhat It Does
Password.ChangePasswordDuration Days 100 Regular password expires after this many days since last change
Password.NewUserDuration Minutes 2880 New users must change their initial password within this many minutes
Password2.ChangePasswordDuration Days 100 2nd level password expires after this many days
Password2.NewUserDuration Minutes 60 New users must change their 2nd password within this many minutes
Login.ValidAttemptCount Count 3 Account locks after this many failed login attempts
Important: NewUserDuration is measured in MINUTES, not days! Here are common conversions:
1,440
= 1 day
2,880
= 2 days (default)
10,080
= 7 days
20,160
= 14 days
43,200
= 30 days

For GEN99122 - New User Password Expiry

This checks whether the new user's initial password has expired.

SELECT
    u.UserName AS [Login ID],
    up.ModifyDate AS [Password Last Changed],
    sp.Value AS [Allowed Duration (minutes)],
    DATEDIFF(MINUTE, up.ModifyDate, GETDATE()) AS [Minutes Since Last Change],
    CASE
        WHEN DATEDIFF(MINUTE, up.ModifyDate, GETDATE()) >= CAST(sp.Value AS INT)
        THEN 'YES - EXPIRED'
        ELSE 'NO - Still valid'
    END AS [Is Expired?],
    DATEADD(MINUTE, CAST(sp.Value AS INT), up.ModifyDate) AS [Expired On],
    CONCAT(
        CAST(CAST(sp.Value AS INT) / 1440 AS INT), ' days ',
        CAST(CAST(sp.Value AS INT) % 1440 / 60 AS INT), ' hours'
    ) AS [Duration in Days/Hours]
FROM [User] u WITH(NOLOCK)
INNER JOIN UserPassword up WITH(NOLOCK) ON u.UID = up.UID
INNER JOIN SysParam sp WITH(NOLOCK)
    ON sp.TenantId = u.TenantId
    AND sp.Name = 'Password.NewUserDuration'
WHERE u.UserName = 'username_here'

For GEN99121 - Regular Password Expiry

This checks whether the regular password has expired.

SELECT
    u.UserName AS [Login ID],
    up.ModifyDate AS [Password Last Changed],
    sp.Value AS [Allowed Duration (days)],
    DATEDIFF(DAY, up.ModifyDate, GETDATE()) AS [Days Since Last Change],
    CASE
        WHEN DATEDIFF(DAY, up.ModifyDate, GETDATE()) >= CAST(sp.Value AS INT)
        THEN 'YES - EXPIRED'
        ELSE 'NO - Still valid'
    END AS [Is Expired?],
    DATEADD(DAY, CAST(sp.Value AS INT), up.ModifyDate) AS [Will Expire / Expired On]
FROM [User] u WITH(NOLOCK)
INNER JOIN UserPassword up WITH(NOLOCK) ON u.UID = up.UID
INNER JOIN SysParam sp WITH(NOLOCK)
    ON sp.TenantId = u.TenantId
    AND sp.Name = 'Password.ChangePasswordDuration'
WHERE u.UserName = 'username_here'

Option A: Reset Password via Admin UI (Recommended)

  1. Log in to flexHR as an admin user
  2. Go to User Management
  3. Find the affected user
  4. Click Reset Password
  5. The system will send a new temporary password to the user
  6. Tell the user to log in and change their password immediately

Option B: Reset via SQL (If Admin UI Is Not Available)

This resets the password state back to "OK" and restarts the expiry timer. The user keeps their current password.

-- Reset password state and timer for a user
-- Replace 'username_here' with the affected user's login ID

UPDATE up
SET up.PwdState = 1,              -- Set to OK (active)
    up.ModifyDate = GETDATE(),    -- Reset the expiry timer to now
    up.NoofInvalidAttempts = 0    -- Clear any failed login attempts
FROM UserPassword up
INNER JOIN [User] u ON u.UID = up.UID
WHERE u.UserName = 'username_here'

-- Verify the change was applied
SELECT u.UserName, up.PwdState, up.ModifyDate, up.NoofInvalidAttempts
FROM [User] u WITH(NOLOCK)
INNER JOIN UserPassword up WITH(NOLOCK) ON u.UID = up.UID
WHERE u.UserName = 'username_here'
After running this: The user can log in with their existing password. Advise them to change it as soon as possible for security.

Option C: Set Password to Never Expire (Special Accounts Only)

-- Only use for service accounts or users approved to bypass expiry
UPDATE up
SET up.PwdNvrExpired = 1
FROM UserPassword up
INNER JOIN [User] u ON u.UID = up.UID
WHERE u.UserName = 'username_here'
Warning: Only use this for service accounts or users specifically approved to bypass password expiry. Do not use for regular employees.

Option D: Increase New User Duration (System-Wide)

If many new users are hitting GEN99122 because 2 days is too short, increase the duration for all new users:

-- Increase new user password validity to 7 days (10080 minutes)
-- Replace TENANT_ID_HERE with the actual Tenant ID
UPDATE SysParam
SET Value = '10080'
WHERE Name = 'Password.NewUserDuration'
AND TenantId = 'TENANT_ID_HERE'

-- Verify
SELECT Name, Value, [Desc]
FROM SysParam WITH(NOLOCK)
WHERE Name = 'Password.NewUserDuration'
AND TenantId = 'TENANT_ID_HERE'

If the error happens during 2nd level authentication (when accessing sensitive pages), check the UserPassword2 table instead:

SELECT
    u.UserName        AS [Login ID],
    up2.PwdState      AS [2nd Password State],
    CASE up2.PwdState
        WHEN 0 THEN 'None'
        WHEN 1 THEN 'OK (Active)'
        WHEN 2 THEN 'LOCKED (Too many failed attempts)'
        WHEN 3 THEN 'Reset by Admin (Pending change)'
        WHEN 4 THEN 'Expired (Must change)'
        WHEN 5 THEN 'New User (Must change initial password)'
    END               AS [State Description],
    up2.PwdNvrExpired AS [Never Expires? (1=Yes, 0=No)],
    up2.ModifyDate    AS [Last Changed On],
    up2.NoofInvalidAttempts AS [Failed Attempts]
FROM [User] u WITH(NOLOCK)
INNER JOIN UserPassword2 up2 WITH(NOLOCK) ON u.UID = up2.UID
WHERE u.UserName = 'username_here'
Note: The 2nd level password has a much shorter default duration:
  • Password2.NewUserDuration = 60 minutes (1 hour)
  • Password2.ChangePasswordDuration = 100 days
Apply the same fixes as Step 4 but target UserPassword2 instead of UserPassword.

Use this to quickly determine the right action:

What error code is the user getting?
GEN99002 - Account Locked
Password State should be 2. Failed attempts exceeded limit.
Fix: Reset NoofInvalidAttempts to 0 via Admin UI or SQL (Option B in Step 4, change PwdState to its original value if it was 1)
GEN99120 - Reset Password Expired
Password State should be 3. Admin reset the password but user didn't change it in time.
Fix: Admin must reset password again (Option A in Step 4)
GEN99121 - Regular Password Expired
Password State should be 4. Password expired after ChangePasswordDuration days.
Fix: User should be redirected to change password page. If stuck, use Option B in Step 4.
GEN99122 - New User Password Expired
Password State should be 5. New user didn't change initial password within NewUserDuration minutes.
Fix: Admin must reset password (Option A or B in Step 4). User cannot self-fix this error.
GEN99128 - Password Record Missing
No UserPassword record exists for this user.
Fix: Escalate to developer. Password record needs to be recreated.
Password State = 1 but user still gets error?
Password is supposedly OK but user can't log in.
Check: Is IsActive = 1? Is PwdNvrExpired set correctly? Escalate to developer if everything looks correct.
