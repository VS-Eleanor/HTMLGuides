Product Architecture

FlexHR System Dependency & Compatibility

Dependencies flow downward. Children depend on parents — never the reverse. Bases are backward compatible.

⚡ 3 Compatibility Rules — Memorize These
1
Upgrading Base never breaks plugins SAFE
If a plugin is compatible with Base 8.6.2, it is guaranteed compatible with 8.6.3, 8.6.4, and so on. We maintain backward compatibility in every base release.
EXAMPLE: eClaim 8.6.1 works on Base 8.6.2 → it will also work on Base 8.6.3
2
Base release never forces a plugin upgrade NO FORCE ↓
When we release a new base version, nobody is required to upgrade their plugins. Plugins continue to work as-is. We do not force plugin upgrades alongside base releases (unless something truly exceptional happens).
EXAMPLE: We release Base 8.6.3 → all existing plugins stay on their current version. No action needed.
3
Plugin upgrade can force a base upgrade MAY FORCE ↑
When upgrading to a newer plugin version, that plugin may require a minimum base version. This is the only direction where an upgrade can force another upgrade — child pulls parent up, never the reverse.
EXAMPLE: eClaim 8.6.2 requires minimum Base 8.6.3 → must upgrade base first before upgrading plugin
TL;DR: We can push base upgrades anytime — plugins won't break. We never force plugin upgrades when releasing a base. But when you choose to upgrade a plugin, you may need to upgrade the base first.
